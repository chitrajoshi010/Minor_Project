# Forest Acoustic Event Detection using TinyML on ESP32-S3

## 1. What is ESP-IDF?

ESP-IDF (Espressif IoT Development Framework) is the official software development kit for Espressif's ESP32 family of microcontrollers. Think of it as the "operating system" + "toolchain" + "libraries" for the ESP32.

**What it provides:**
- A build system (CMake + Ninja) that compiles C/C++ code for the ESP32's Xtensa CPU
- Hardware drivers for I2S (audio), GPIO, SPI, I2C, etc.
- FreeRTOS — a real-time operating system for task scheduling
- Networking stack (WiFi, TCP/IP, Bluetooth)
- Library manager (`idf_component.yml`) to install pre-built components like `esp-tflite-micro` and `esp-dsp`

**Key commands:**
```bash
source ~/esp/esp-idf/export.sh    # Activate ESP-IDF environment
idf.py build                        # Compile the project
idf.py -p /dev/ttyACM0 flash        # Flash firmware to ESP32
idf.py -p /dev/ttyACM0 monitor      # View serial output in real-time
```

## 3. How the Model Was Deployed on the ESP32

The model goes through a conversion pipeline from Python → C array:

```
train_tiny_model.py  →  tiny_int8.tflite  →  model_data.h  →  ESP32 firmware
      (training)        (INT8 quantized)     (C array)       (flash to board)
```

**Step 1: Train in Python** (`notebooks/train_tiny_model.py`)
- Uses TensorFlow/Keras on the PC
- Trains a CNN on 2.5s log-mel spectrograms from the FSC22 dataset
- Achieves ~93% float32 accuracy on the test set

**Step 2: INT8 Quantize**
- Converts float32 weights + activations to INT8 using a representative dataset (100 training samples)
- Reduces model size from ~173 KB (float32) → 19 KB (INT8)
- Necessary because ESP32-S3 has no hardware float acceleration

**Step 3: Convert to C array** (`scripts/tflite_to_c.py`)
- Takes the `.tflite` flatbuffer file
- Wraps it as `const unsigned char model_data[] = { 0x1c, 0x00, ... };`
- Output: `model_data.h` with 18,664 bytes of hex data

**Step 4: Include in Firmware**
- `main.cpp` includes `model_data.h`
- The model is stored in **flash memory** (not RAM), consuming 19 KB of the 2 MB flash
- At boot, `tflite::GetModel(model_data)` reads the model from flash
- The TensorFlow Lite Micro interpreter allocates memory in the **tensor arena** (260 KB static buffer in DRAM) for intermediate activations

**Step 5: Flash to ESP32**
- `idf.py -p /dev/ttyACM0 flash` writes the firmware binary to the board's flash memory
- On every power-up, the ESP32 loads this firmware from flash and runs `app_main()`

## 4. How the Microphone Works

### Hardware: INMP441 MEMS Microphone

The INMP441 is a digital microphone that outputs audio directly in I2S format — no ADC needed.

**Pin connections:**
```
INMP441      ESP32-S3
─────────────────────
VDD    →     3.3V
GND    →     GND
SCK    →     GPIO 17  (I2S bit clock)
WS     →     GPIO 15  (I2S word select / frame sync)
SD     →     GPIO 16  (I2S serial data in)
L/R    →     GND      (selects left channel output)
```

### Protocol: I2S (Inter-IC Sound)

I2S is a standard digital audio interface with three lines:
- **BCK (Bit Clock):** The ESP32 generates this clock at 16 kHz × 16 bits × 2 channels = 512 kHz
- **WS (Word Select):** Toggles at 16 kHz — LOW for left channel, HIGH for right channel
- **SD (Serial Data):** The microphone sends 16-bit audio samples synchronized to BCK and WS

### Software: ESP-IDF I2S Driver (`audio_capture.cpp`)

```cpp
i2s_std_config_t std_cfg = {
    .clk_cfg = I2S_STD_CLK_DEFAULT_CONFIG(SAMPLE_RATE),   // 16 kHz
    .slot_cfg = I2S_STD_PHILIPS_SLOT_DEFAULT_CONFIG(
        I2S_DATA_BIT_WIDTH_16BIT, I2S_SLOT_MODE_MONO),    // 16-bit mono
    .gpio_cfg = { .bclk = GPIO_NUM_17, .ws = GPIO_NUM_15, .din = GPIO_NUM_16 },
};
```

- **Sample rate:** 16,000 Hz (SAMPLE_RATE in spectrogram_params.h)
- **Bit depth:** 16 bits per sample
- **Channels:** Mono (single microphone)
- **DMA:** 8 DMA descriptors with 512 frames each — allows the I2S peripheral to capture audio in the background without CPU intervention

The `audio_init()` function configures and starts the I2S peripheral. The `audio_capture()` function reads samples from the I2S DMA buffer into a user-provided buffer:

```cpp
esp_err_t audio_capture(int16_t *buffer, size_t num_samples)
{
    // Reads num_samples 16-bit values from I2S into buffer
    // Blocks until all samples are received
}
```

The audio samples are **int16_t** values ranging from -32768 to +32767, representing the microphone's analog signal amplitude.

## 5. When Does It Capture? The Main Loop

**It captures AUTOMATICALLY — no script, no trigger, no button.**

The ESP32 runs a continuous loop once powered on:

```
ESP32 boots
    ↓
app_main() starts
    ↓
Load model from flash
    ↓
Initialize TFLite interpreter + 260 KB tensor arena
    ↓
Initialize I2S microphone
    ↓
Initialize FFT (ESP-DSP library)
    ↓
┌─────────────────────────────────────────────┐
│  Loop forever:                               │
│                                              │
│  1. Print "--- Capturing 2.5s + spectrogram..."│
│  2. Call spectrogram_compute()                │
│     ├── Captures 40,000 audio samples from I2S│
│     │   (takes ~2.5 seconds in real-time)     │
│     ├── Computes 64×251 log-mel spectrogram   │
│     ├── Normalizes and quantizes to INT8      │
│     └── Fills input_tensor                    │
│  3. Print "[OK] Spectrogram computed"         │
│  4. Call interpreter.Invoke()                 │
│     (runs the neural network — ~50-100 ms)    │
│  5. Print prediction result                   │
│  6. Wait 1 second                             │
│  └── Repeat                                   │
└─────────────────────────────────────────────┘
```

**Timing of one complete cycle:**
- Audio capture: ~2.5 seconds (real-time, since we capture at 16 kHz for 40,000 samples)
- Spectrogram computation: ~0.5-1 second (FFTs, Mel filtering, normalization)
- Inference: ~50-100 ms (TFLite Micro on ESP32-S3)
- Wait: 1 second
- **Total: ~4-4.5 seconds per cycle**

**When you see `--- Capturing 2.5s + spectrogram...`** on the serial monitor, the device is actively listening. Make your sound during this phase.

## 6. The Audio Pipeline — Step by Step

This is what happens inside `spectrogram_compute()` in `spectrogram.cpp`:

### Step 1: Audio Capture
```
I2S microphone → int16_t ring buffer (512 samples)
                 ↓
        40,000 samples captured over 2.5 seconds
                 ↓
        Samples stored in circular buffer for sliding window access
```

### Step 2: Framing
The 2.5s audio is divided into 251 overlapping frames:
```
Frame 0: samples [-256 .. 255]   (first 256 samples are zero-padded)
Frame 1: samples [-156 .. 355]   (slides by HOP_LENGTH=160 samples)
Frame 2: samples [-56  .. 455]
...
Frame 250: samples [39744 .. 40255]
```
Each frame is 512 samples (32 ms at 16 kHz), with 10 ms hop between frames.

### Step 3: Hann Window
Each 512-sample frame is multiplied by a Hann window to reduce spectral leakage:
```
fft_input[i] = frame[i] × hann_window[i]
```

### Step 4: FFT (Fast Fourier Transform)
A 512-point real FFT converts each frame from time-domain to frequency-domain:
```
fft_input (512 real) → FFT → 257 frequency bins (magnitudes)
```
The magnitude is `sqrt(re² + im²)` for each bin.

### Step 5: Mel Filterbank
The 257 FFT magnitude bins are weighted and summed into 64 mel-scale bands:
```
mel_energy[m] = Σ(magnitude[k] × mel_filterbank[m][k])  for k=0..256
```
The mel scale is psychoacoustic — it emphasizes lower frequencies where humans (and forest sounds) are most sensitive.

### Step 6: Log Compression
Each mel band energy is converted to decibels:
```
log_mel[m] = 10 × log10(mel_energy[m] + 1e-10)
```
The `+ 1e-10` avoids `log(0)`. Values range from approximately -100 dB (silence) to 0 dB (loud).

### Step 7: Normalization
Compute the mean and standard deviation of all 64×251 = 16,064 log-mel values, then normalize each value:
```
normalized = (log_mel - mean) / std
```
This is called "per-sample z-score normalization" — it makes the model invariant to absolute volume (a quiet chainsaw sounds the same as a loud chainsaw after normalization).

### Step 8: INT8 Quantization
The normalized values (float32) are quantized to INT8 using the model's input quantization parameters:
```
q = round(normalized / input_scale + input_zero_point)
q = clamp(q, -128, 127)
```
Where `input_scale = 0.053753` and `input_zero_point = 17`.

### Step 9: TFLite Inference
The 64×251×1 INT8 tensor is fed to the neural network via `interpreter.Invoke()`. The model runs through:
1. Conv2D (8 filters, 3×3) → BatchNorm → MaxPool (2×2)
2. Conv2D (16 filters, 3×3) → BatchNorm → MaxPool (2×2)
3. Conv2D (32 filters, 3×3) → BatchNorm → MaxPool (2×2)
4. Global Average Pooling
5. Dense (64 units) → Dropout
6. Dense (6 units) → Softmax

### Step 10: Output
The output is 6 INT8 values (one per class) which are dequantized:
```
probability[i] = (output[i] - output_zero_point) × output_scale
```
The class with the highest probability is the prediction.

## 7. Memory Map on ESP32-S3

Here is exactly how the ESP32-S3's memory is used:

### Flash (2 MB)
| What | Size |
|---|---|
| Bootloader | 20 KB |
| Partition table | 3 KB |
| **Firmware (our code + model)** | **~456 KB** |
| Free | ~909 KB |

### Internal SRAM (~512 KB)
| What | Size | Location |
|---|---|---|
| FreeRTOS kernel + tasks | ~30 KB | DRAM |
| I2S DMA buffers | 8 KB | DRAM |
| **Tensor arena (TFLite)** | **260 KB** | Static DRAM |
| Stack (main task) | 12 KB | DRAM |
| **Log-mel buffer** | **32 KB** | Heap (DRAM) |
| FFT buffer | 4 KB | Heap (DRAM) |
| Magnitude buffer | 1 KB | Heap (DRAM) |
| Ring buffer | 1 KB | Stack |

**Why we struggled:**
- Original float log-mel buffer was 64 KB → heap couldn't find a contiguous 64 KB block after allocating other buffers → `ESP_ERR_NO_MEM`
- Fix: Switched to `int16_t` scaling, halving to 32 KB → fit in largest free block
- Stack overflow: `float fft_buf[1024]` = 4 KB on stack, main task stack was only 3.5 KB → moved to heap

## 9. How to Use It Later

### To power it on:
- Connect the ESP32-S3 to any USB port (USB cable to your laptop, power bank, or USB wall adapter)
- It will boot automatically and start running the classifier
- No WiFi needed, no configuration needed — standalone operation
- If you want to see the output, connect via serial monitor

### To view predictions:
```bash
cd ~/esp/forest_acoustic_classifier
source ~/esp/esp-idf/export.sh
idf.py -p /dev/ttyACM0 monitor
```
Press `Ctrl+]` to exit the monitor.

### To reflash (update firmware):
```bash
cd ~/esp/forest_acoustic_classifier
source ~/esp/esp-idf/export.sh
idf.py -p /dev/ttyACM0 flash monitor
```

### To change model or parameters:
1. Train a new model in `/home/santosh/Videos/archive/notebooks/`
2. Convert to TFLite: `train_tiny_model.py`
3. Convert to C array: `scripts/tflite_to_c.py`
4. Replace `main/model_data.h`
5. Update `main/spectrogram_params.h` if input shape changed
6. Rebuild and flash

### To deploy in the field (no USB):
The ESP32-S3 can be powered by:
- USB power bank (5V)
- 3.7V LiPo battery (via the battery connector, if the board has one)
- 5V solar panel + regulator (for outdoor deployment)

The classifier runs standalone — just power on and it works.

## 10. Summary of All Changes Made

| Problem | Symptom | Fix |
|---|---|---|
| Model too large | DRAM overflow, tensor arena wouldn't fit | Trained tiny model [8,16,32] with 64 mel bands, 2.5s |
| Heap allocation failed | `ESP_ERR_NO_MEM` at runtime | Switched log-mel buffer from float (64 KB) → int16_t (32 KB) with LOG_MEL_SCALE=100 |
| Stack overflow | Device rebooted during spectrogram | Moved fft_buf and magnitude from stack to heap; increased main task stack from 3.5 KB to 12 KB |
| Microphone only returned zeros | Always predicted same class | Fixed L/R pin wiring (must be connected to GND) |
| INT8 accuracy drop | 92.5% → 86.67% on full model | Tiny model achieved 87.92%, actually better |
